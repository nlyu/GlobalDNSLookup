How Global DNS Lookup works

What is Global DNS Lookup?

Global DNS Lookup is a practical troubleshooting tool for comparing how a domain may resolve for users in different parts of the world. Enter one domain and the tool sends DNS-over-HTTPS requests with representative EDNS Client Subnet values. Results appear progressively, so you can begin comparing countries without waiting for every lookup to finish.

The tool focuses on the records most often involved in website and CDN routing: A records for IPv4, AAAA records for IPv6, and the CNAME chain that connects a hostname to an edge or service hostname. Each result also identifies the recursive resolver that returned it and preserves DNS time-to-live values.

Why can DNS results differ by country?

Modern DNS is frequently location-aware. CDNs and traffic managers may return different addresses according to the apparent client network, resolver location, service health, capacity or policy. Recursive DNS caches can also hold answers obtained at different times. Two users in the same country can therefore receive different results when they use different ISPs or recursive resolvers.

EDNS Client Subnet, usually called ECS, lets a recursive resolver include a shortened network prefix in its request to an authoritative DNS server. The authoritative service can use that prefix when selecting an answer. This site supplies configured, representative prefixes; it does not send the visitor's address as the simulated location.

What is an A record?

An A record maps a hostname to one or more IPv4 addresses, such as 192.0.2.10. It remains the most common record used to direct web traffic to servers and CDN edges.

What is an AAAA record?

An AAAA record maps a hostname to an IPv6 address. A domain may have A records, AAAA records, both, or neither. The absence of an AAAA record is a normal DNS result rather than a lookup failure.

What is a CNAME record?

A CNAME makes one hostname an alias of another. Large services often use several CNAME steps before reaching A or AAAA records. This tool displays the chain found in the resolver responses.

Why compare resolvers?

Recursive resolvers can differ in reachability, cache state, ECS behavior and filtering policy. The resolver label makes fallback behavior visible instead of presenting results as though every provider answered identically.

How should these results be interpreted?

Treat each row as a simulation for one selected network prefix, not as a guarantee for an entire country. For production incidents, compare these results with tests from the affected ISP, an actual regional probe, authoritative DNS logs and your CDN control plane. The tool is designed to reveal useful differences quickly, while keeping the limits of geographic DNS simulation clear.
